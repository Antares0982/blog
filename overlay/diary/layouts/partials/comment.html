{{/* Override of themes/diary/layouts/partials/comment.html, reduced to the one comment system this site uses, with two additions upstream's template has no way to express: data-term. The mapping is `specific` rather than `pathname` because the slug outlives the path. Five pages moved from // to /words// once the migration started honouring WordPress's page hierarchy, and three more were renamed out of Chinese slugs; pathname mapping would have orphaned every comment on all eight. The slug also survives the move back to the apex domain, and reads as a title on GitHub. data-loading. giscus.app hands you `data-loading="lazy"` when you tick the lazy-loading box, but upstream's template drops the attribute, so setting it in config alone does nothing. It keeps the iframe out of the initial load, which is the whole point of this rebuild. The term carries the language for everything but the default one, so /python-json/ maps to `python-json` and /en/python-json/ to `en/python-json`. The two articles are the same subject but not the same conversation, and the Chinese terms must not shift: the migrated WordPress comments are seeded against the bare slugs. */}} {{- $term := .Params.slug | default .File.ContentBaseName -}} {{- with site.LanguagePrefix }}{{ $term = printf "%s/%s" (strings.TrimPrefix "/" .) $term }}{{ end -}} {{ if and .Site.Params.enableGiscus (ne .Params.comment false) }} {{ end }}
